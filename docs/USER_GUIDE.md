## 2. 角色与权限

| 角色 | 标识 | 能做什么 |
|------|------|----------|
| **超级管理员** | `super_admin` | 全部功能：用户管理、设备管理、变更审批、审计查询 |
| **区域操作员** | `zone_operator` | 已授权区域的记录新增 / 修改 / 删除（可走审批） |
| **审批人** | `approver` | 审批变更申请，无直接编辑权限 |
| **只读用户** | `zone_viewer` | 查看区域与记录，无任何写权限

> 区域操作员的「能操作的区域」由管理员在「用户管理」中按区域分配。

## 3. 核心场景

### 3.1 浏览 DNS 区域

**菜单** → 「区域列表」

界面会列出所有从 F5 同步过来的 DNS 区域。每个区域卡片显示：

| 字段 | 说明 |
|------|------|
| 区域名 | 例如 `ppv2.com` |
| 类型 | master / slave / forward |
| View | external / internal / ... |
| 设备 | 所属 F5 设备名 |
| 记录数 | 该区域当前记录条数 |
| 最后修改 | 时间 + 修改人 |

**操作**：

- 点击「详情」→ 进入区域，查看 SOA / NS / A / AAAA / CNAME / MX / TXT 等记录
- 点击「同步」→ 重新从 F5 拉取该区域（只读刷新）
- 点击「导出」→ 下载 zone 文件原文（用于审计）

---

### 3.2 新增一条 DNS 记录

**菜单** → 「记录管理」→ 选择目标区域 → 「新增记录」

#### 表单填写

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| 主机记录 | 是 | 子域名前缀或 `@` | `www` |
| 记录类型 | 是 | A / AAAA / CNAME / MX / TXT / NS / SRV / PTR | `A` |
| 记录值 | 是 | 实际值 | `192.0.2.10` |
| TTL | 否 | 秒，默认 3600 | `300` |
| 备注 | 否 | 业务描述 | `门户主入口` |

#### 填写示例

| 场景 | 主机记录 | 类型 | 值 | TTL |
|------|----------|------|-----|-----|
| 域名主入口 | `@` | A | `192.0.2.10` | 3600 |
| www 子域 | `www` | A | `192.0.2.10` | 3600 |
| CDN 别名 | `cdn` | CNAME | `cdn.example.com.cdn.dnsv1.com.` | 600 |
| 邮件服务器 | `@` | MX | `10 mail.example.com.` | 3600 |
| SPF 记录 | `@` | TXT | `"v=spf1 include:_spf.example.com -all"` | 3600 |

#### 提交

1. 填写完毕 → 「提交申请」
2. 若启用了审批流：申请进入「待审批」，等审批人通过
3. 若未启用审批：直接执行，5 秒内返回结果

#### 系统自动行为

- SOA serial 自动 +1
- 原 zone 文件自动备份到 `zone_backups` 表
- F5 上同步生成 `<zone>.bak.<serial>` 文件
- 写入 `audit_log`

---

### 3.3 修改 / 删除记录

#### 修改

「记录列表」→ 找到目标记录 → 「编辑」→ 修改值/TTL → 「提交」。

> 修改主机记录名等同于「删除原记录 + 新增记录」，会产生两次审计与备份。

#### 删除

「记录列表」→ 目标记录 → 「删除」→ 输入二次确认 → 「提交」。

> 系统保留删除前的完整 zone 备份，可一键回滚。

---

### 3.4 变更审批流程

当管理员开启了「变更审批」（默认开启）：

```
申请人 (zone_operator)                审批人 (approver)
         │                                  │
   ┌─────▼─────┐                     ┌──────▼──────┐
   │ 提交申请  │                     │  待审批列表  │
   │ (pending) │ ──────────────────▶ │  查看 diff  │
   └───────────┘                     └──────┬──────┘
                                             │
                                  ┌──────────┴─────────┐
                                  │                    │
                            ┌─────▼─────┐        ┌─────▼─────┐
                            │  批准      │        │  拒绝      │
                            │ (approved)│        │ (rejected)│
                            └─────┬─────┘        └────────────┘
                                  │
                                  ▼
                          ┌───────────────┐
                          │ 自动执行变更   │
                          │ (executed)    │
                          └───────────────┘
```

#### 申请人视角

1. 「变更申请」→ 「我的申请」→ 查看状态：待审批 / 已批准 / 已执行 / 已拒绝
3. 被拒绝时可看到「拒绝理由」，可编辑后重新提交

#### 审批人视角

1. 「变更申请」→ 「待审批」→ 看到申请列表
2. 点击「详情」→ 查看变更前后 diff（记录值、TTL 等）
3. 「批准」或「拒绝」→ 填写意见

#### 紧急通道

`super_admin` 可绕过审批直接生效（仅限紧急情况，操作会被审计标记 `bypass=true`）。

### 3.5 查看与回滚备份

**菜单** → 「记录管理」→ 选中区域 → 「备份历史」

每条备份显示：

| 字段 | 说明 |
|------|------|
| 备份时间 | UTC+8 |
| SOA serial | 备份时的版本号 |
| 触发原因 | 写操作类型 / 手工备份 |
| 备份人 | 操作者 |

**回滚**：

1. 选中目标备份 → 「回滚到此版本」
2. 系统会：
   - 备份当前 zone 文件（保护链）
   - 覆盖写入 F5
   - `rndc reload`
3. 回滚本身会产生审计记录

---

### 3.6 查看审计日志

**菜单** → 「审计」

支持筛选：

- 时间范围
- 操作人
- 操作类型（login / record_add / record_modify / ...）
- 目标资源
- 状态（success / failure）

每条审计行显示：时间、用户、操作、目标、IP、状态、详情链接。

可导出 CSV（仅 `super_admin`）。

## 4. 设备管理（管理员）

**菜单** → 「设备管理」

### 4.1 新增 F5 设备

| 字段 | 必填 | 说明 |
|------|------|------|
| 设备名称 | 是 | 中文友好名，如「上海数据中心-01」 |
| 主机 IP | 是 | F5 管理口 IP |
| SSH 端口 | 是 | 默认 22 |
| 用户名 | 是 | 推荐专用账号 `dnsmanager` |
| 认证方式 | 是 | 密钥（推荐）/ 密码 |
| 私钥路径 | 条件 | 容器内路径，如 `/app/keys/sh-01` |
| 私钥密码 | 否 | 加密私钥才需要 |
| named.conf 路径 | 是 | 默认 `/var/named/config/named.conf` |
| zone 目录 | 是 | 默认 `/var/named/config/namedb/` |
| 启用 | 是 | 立即启用 / 仅保存 |

保存后**重启 backend 容器**使 SSH 连接器加载新设备：

```bash
docker compose -f docker-compose.lite.yml restart backend
```

### 4.2 测试连接

设备列表行 → 「测试连接」按钮。

返回：

```json
{
  "success": true,
  "latency_ms": 23,
  "message": "SSH 连接 OK, named 配置可读"
}
```

或失败信息（如认证失败、路径不存在）。

## 5. 用户管理（管理员）

**菜单** → 「用户管理」

### 5.1 新增用户

| 字段 | 必填 | 说明 |
|------|------|------|
| 用户名 | 是 | 登录名（小写英文，3-20 字符） |
| 初始密码 | 是 | ≥ 8 位含大小写数字 |
| 显示名 | 是 | 界面显示 |
| 邮箱 | 否 | 接收审批通知 |
| 角色 | 是 | 4 选 1 |
| 区域授权 | 条件 | zone_operator / zone_viewer 必填 |

### 5.2 重置密码

选中用户 → 「重置密码」→ 输入新密码（系统会强制首次登录修改）。

### 5.3 禁用 / 启用

禁用后该用户无法登录，但历史审计保留。

## 6. 常见问题

### Q1：提交变更后状态一直是「待审批」？

A：检查审批人是否在岗。「变更申请」→「待审批」列表里所有 approver 都能看到。

### Q2：执行变更后 F5 上没生效？

A：
1. 看 `audit_log` 是否成功
2. SSH 到 F5：`rndc status` 查看加载状态
3. 客户端 `dig @<f5-ip> <zone> <record>` 验证

### Q3：备份很多，怎么清理？

A：「系统设置」→「备份保留策略」→ 默认保留 30 天，可改为 7 / 90 天。过期备份自动清理。

### Q4：忘记了 admin 密码？

A：服务器上执行：

```bash
docker compose -f docker-compose.lite.yml exec backend python -c "
import asyncio
from app.database import async_session_factory
from app.models import User
from app.core.auth import hash_password
async def t():
    async with async_session_factory() as db:
        from sqlalchemy import select
        r = await db.execute(select(User).where(User.username=='admin'))
        u = r.scalar_one()
        u.password_hash = hash_password('NewStrongPassword!')
        await db.commit()
asyncio.run(t())
"
```

### Q5：能否批量导入记录？

A：当前 UI 不支持。变通方案：

1. 准备 zone 文件片段
2. 通过 SSH 直接放到 F5 的 `<zone_dir>/db.<zone>.inc.local`（BIND include 机制）
3. `rndc reload`

未来版本会提供「CSV 导入」功能。
